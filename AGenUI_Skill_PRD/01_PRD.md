# AGenUI 生成式回复 Skill｜产品需求文档（PRD）

> 本项目的是对标“Intelligent UI 效果”：按用户意图组织信息、选择控件、生成A2UI、在本地互动。它不表示复刻或接入 ChatGPT 私有协议。
## 决策摘要

采用 **Skill + 版本化能力清单 + 参考风格约束 + A2UI 校验与投递 + 端侧状态/动作运行时**。

模型负责选择信息结构、组装组件、声明已支持的绑定与函数；端侧负责渲染、响应式求值、输入保护、真实动作。

“简洁”定义为视觉秩序和内容密度，不等于只用 Text。“丰富”定义为每个控件都服务于任务，不等于一条回复必须展示全部组件。

P0 以两类样例为验收主线：

| 主线 | 用户价值 | 参考形式 | 关键验收 |
|---|---|---|---|
| 方案比较与选择 | 在多个选项中作决定并继续细化 | 杭州路线卡 | 表格、单选、点击时读取当前选项、继续对话 |
| 参数调整与测算 | 修改输入，立即看到结果 | 火锅食材测算台 | 双滑块、嵌套计算、日期和多选、提交当前快照 |


### Skill引导模型的目标

| 目标 | 产品定义 |
|---|---|
| G1 意图适配 | 用户问答选择丰富且适配的 UI |
| G2 风格一致 | 固定视觉语言，可参考sources里面已有的样例；允许因任务改变组件组合，不随机改变配色与密度 |
| G3 可交互 | 输入有绑定、结果有依赖、动作有接收方和反馈 |
| G4 渐进可用 | 完整且有意义的区域逐步出现，不等整份 JSON 完成才展示 |
| G5 状态连续 | 可使用已注册的函数根据用户交互在端侧实现多轮对话 |


### 用户与使用场景

直接用户是通过自然语言提出任务的人；运营/开发人员管理视觉规则和示例；Skill/Agent 工程师维护生成约束；客户端工程师维护实际能力与交互运行时；


### 参考信息

1. sources中两份文件为仅使用updateComponents的端侧可渲染的示例DSL，Skill指导生成的DSL要保持和该示例相同的美学规则，必要时总结示例的美学规则；
2. Skill指导生成的DSL可使用的组件协议应参考https://genui.amap.com/components；
3. Skill指导生成的DSL可被高德AgenUI的渲染器渲染https://github.com/AGenUI/AGenUI/tree/main/playground/harmony；
4. Skill中指导生成A2UI的流程可以参考https://github.com/AGenUI/AGenUI/tree/main/skills/a2ui-generation，但不能照抄，要保证可以生成sources中的示例；

## 规范注意

### 生成的DSL要采用共同视觉语言

白色或中性浅色卡片；黑灰层级文字；较大圆角；尽量不使用对比明显的颜色

### 功能规范

1. SKill要有层级及低耦合性，例如：Skill所使用的组件库和端侧提供支持的能力分别用单独目录承载，并且每个组件和功能划分清晰；
2. 当前Skill仅支持高德AgenuUI的22个组件，示例组件暂未支持，但后续有可根据项目进行支持的能力；
3. 当前端侧已支持functioncall的能力有calculatenumer和sendMsgToXy，具体使用方法参考sources中的示例；
4. Skill要指导模型根据用户意图和获取到的信息使用尽可能丰富的组件和交互来提升用户的沉浸和方便体验；
4. DSL中可变数据的绑定是用路径绑定的，非id绑定；
5. Skill指导生成的DSL支持端侧流式渲染；
6. Skill要使用中文，同时整个方案的设计与演进单独落一个目录；
