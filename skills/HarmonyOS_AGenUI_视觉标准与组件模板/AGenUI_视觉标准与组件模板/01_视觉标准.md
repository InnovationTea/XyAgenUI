# AGenUI 富交互回复视觉标准

**状态：项目候选标准 v1.1-vp；2026-11-17 核对来源，2026-11-18 按用户确认的端侧vp约定更新。** 以 HarmonyOS 手机设计规范为视觉依据，结合 AGenUI 官方 Skill 的信息组织原则；实现约束使用你上传的 `agenui-reply` 的有效 Catalog，而不是自动迁移线上最新版。

> 交付目标：组件外观标准化，页面结构自由生成，数据与交互保持动态。不是一套固定火锅页或旅行页，也不是改写 A2UI 协议。

## 0. 如何区分依据

- **[H] 官方视觉依据**：华为开发者文档；保留设备范围、单位和推荐/必须等级。
- **[A] 官方生成指导**：AGenUI Skill、组件说明与 API；其中的卡片设计策略不都属于协议硬约束。
- **[P] 项目设计决策**：本次为你的单轮在线 Skill 制订的取值、组合和例外，不能称为两家共同发布的标准。
- **[R] 运行时限制**：你项目锁定的 Catalog、profile 与兼容覆盖；最终仍需真机确认。

来源编号详见 `sources.json` 和 `docs/来源与差异.md`。本次没有读取成功的 AGenUI `spacing-elevation` 等子文档，未被拿来支撑具体间距或圆角数值。

## 1. 决策优先级

1. 用户明确需求、业务真实性、安全与可访问性。
2. 目标端实际启用的组件、字段、函数、主题能力。
3. 采用的设备视觉规范及用户已确认的项目端侧单位约定。
4. 项目统一设计值、组件语义变体和组合规则。
5. 装饰性表现。

如果设计效果超出字段能力，不写“看起来像 CSS”的未知属性；采用受支持替代或由宿主补足。不得为校验通过删除真实业务含义。

## 2. 字体与字号

### 2.1 原始官方规范，不先做单位换算

[H / H01] 当前文本排版文档将文字分成展示、标题、副标题、正文、说明。手机列的选取值如下：

| 官方角色 | 手机设计值 | 文档字重 |
|---|---:|---|
| Display_S | 38 vp | Light |
| Title_L / Title_M / Title_S | 30 / 24 / 20 vp | Bold |
| Subtitle_L / M / S | 18 / 16 / 14 vp | Medium |
| Body_L / M / S | 16 / 14 / 12 vp | Medium / Regular / Regular |
| Caption_L / M | 12 / 10 vp | Medium |

这些是手机列，不是 PC 或手表列；新旧版文档也不混合。规范有 10vp 说明文字，不表示本项目应把普通说明压到 10vp。

[A / A03] 本次可读的 AGenUI `component-catalog.md` 另有一套直接输出的字体尺度：全局标题 40px、分区 36px、正文 32px、小字 28px、标签脚注 24px。这是一套 Skill 输出约定，不能将 32px 直接解释为 32vp，也不能认为它与华为所有角色一一对应。

### 2.2 本项目语义字号 [P]

| 项目角色 | 默认设计值（vp） | 项目字重 | 使用规则 |
|---|---:|---|---|
| page | 30 | bold | 一条回复的主要标题；卡片级简短回复可省略 |
| group | 24 | bold | 明确独立的大区块 |
| section | 20 | bold | 卡片标题与常规分区标题 |
| subheading | 18 | bold | 小分组，不与 section 同时滥用 |
| body | 16 | normal | 正文和主要标签 |
| hint | 14 | normal | 辅助说明，不承载唯一的关键操作信息 |
| caption | 12 | normal | 单位、短来源、非核心补充 |
| metric | 38 | bold | 短的关键数值；字重是项目强调选择，非照搬 Display_S Light |
| button | 16 | bold | 按钮文字；保持可读与触达 |

上表是以默认字体比例下的鸿蒙逻辑设计值为目标。项目有意将正文和部分标签使用 normal/bold 两档，减少不同 Native 实现对 Medium 的差异；不是声称与所有系统 Token 字重完全相同。

默认每个区域只用标题、正文、辅助三级；数值区才额外使用指标样式。不要在一张卡片中展示完整字号表。

### 2.3 项目统一使用vp，保留官方来源的单位 [P/R]

用户已确认当前端侧支持 vp，尺寸无单位时默认 vp。本包的字号、宽高、内外边距、gap、圆角、边框等长度直接按逻辑设计值输出，默认 `lengthScale=1, fontScale=1`。正文输出 `"16vp"`、卡片内边距输出 `"16vp 16vp 16vp 16vp"`、页面标题输出 `"30vp"`；旧版2倍输出候选已撤销，不把旧32px简单换后缀成32vp。

尺寸字段保持目标Schema的字符串类型。默认显式写 `"16vp"`；允许无单位字符串的尺寸字段中，`"16"`按vp解释。复合尺寸同样保留字符串，例如按钮内边距 `"12vp 20vp 12vp 20vp"`。这项单位约定不将尺寸字段扩展为JSON数值型。

上游原始Catalog的px描述及原始pattern作为来源保留；离线检查复用宿主 `loadCatalog(profile)` 的项目vp单位overlay，允许vp及原有兼容写法，模板新输出统一使用vp。上游可接收px并不改变本项目默认单位，也不证明官方已声明vp支持。

[H / H06] fp默认与vp对应，系统大字体设置可能改变文字显示比例。用户确认的是当前端侧的尺寸语义，系统大字体、宿主原生文字行为和无障碍缩放仍需单独验收；生成器的 `fontScale=1` 不等于已经实现或验证了这些行为，也不应再次乘系统字体比例。

`line-height: 1.5` / `1.3` 保持无单位倍率；百分比、`aspect-ratio`、opacity、计数和Slider的min/max/value等业务数量保持原义，不能给它们统一加vp。

`examples/unit_calibration.ndjson` 保留文件名，内容改为16/32/48三个值的显式vp字符串与无单位字符串配对，供核对显示等价性及原生参考尺寸。此文件不再用于猜测2倍换算，生成和Schema通过也不代表真机视觉验收完成。

### 2.4 排版规则 [P，依据 H01/A01]

正文建议行高 1.5，标题和短指标 1.3；这是项目取值。正文自然增高，不通过固定高度或省略号藏掉信息。完整文字省略 Text 的 `line-clamp`；需要摘要时使用当前宿主允许的正整数（推荐3）。**不传播到 RichText**。按钮、价格、单位和时间被挤碎时，优先换布局，不继续缩小字体。系统默认字体优先，无法确认字体安装时不指定一个陌生字体家族。

## 3. 色彩体系

### 3.1 官方原则 [H / H02]

采用语义角色，而不是让每个卡片各选一种颜色。Primary、Brand、Container、背景和 on 系列的用途不同；亮暗模式保持语义角色，具体值可变化。尤其反色前景是放在强调容器或图片之上，不能到处套白字。

华为文档表中的官方例值包括：亮色品牌 `#FF0A59F7`、亮色容器白 `#FFFFFFFF`、灰背景 `#FFF1F3F5`，深色容器 `#FF202224`。这些值在原表中使用 ARGB。

### 3.2 ARGB → RGBA 的映射陷阱 [H/R]

华为表为 `#AARRGGBB`；AGenUI 目录描述的是 `#RRGGBBAA`：

```text
华为  #FF0A59F7 → AGenUI #0A59F7（不透明）
华为  #330A59F7 → AGenUI #0A59F733 或 rgba(10,89,247,0.2)
华为  #19000000 → AGenUI #00000019
```

不能把八位字符串原封不动搬过来。完全不透明时优先六位 HEX，降低生成错误。

### 3.3 项目调色板 [P]

| 语义 | 亮色 | 深色 | 说明 |
|---|---|---|---|
| page | #F1F3F5 | #111315 | 页面底色，深色值为项目选择 |
| surface | #FFFFFF | #202224 | 主卡片 |
| primary | #16181D | #F4F5F6 | 主要文本 |
| secondary | #343A40 | #D5D9DF | 正文 |
| muted | #555D66 | #AEB6C2 | 辅助文字，仍要可读 |
| accent | #0A59F7 | #8CB6FF | 高亮文字/选择指引；深色值为项目选择 |
| tint | #EEF4FF | #182B48 | 弱强调容器 |
| action / onAction | #16181D / #FFFFFF | #F4F5F6 / #16181D | 延续你当前黑白主按钮风格 |
| divider | #D5DAE0 | #3D444D | 仅装饰性分割；不是输入框的唯一识别边界 |
| inputBorder | #7A838F | #838D9B | 需要明确边界时的项目候选色 |
| error | #B42318 | #FFB4AB | 错误文字＋文字/图标语义，不仅靠颜色 |
| success | #027A48 | #76D6A4 | 成功反馈 |
| warning | #9A6700 | #EFC46A | 注意信息 |

除前节明确标为官方例值的色彩外，以上是可访问性优先的项目配色，不是华为官方 Token 全表。深色版本尤其不能仅做图像反色。

### 3.4 半透明与背景图 [P]

保留你喜欢的主题背景与半透明卡片，但属于可选表达，不是每轮必须检索图片。图片必须已经可用且不会阻塞首批内容。卡片可用 `rgba(255,255,255,0.96)` 作为候选；其可读性应在实际图片合成之后检查。

不使用组件整体 opacity 来“做玻璃”，否则文字与控件一起变淡。没有经确认的 blur 字段，就不输出 `backdrop-filter`。无图片、网络失败、对比不足时使用不透明卡片和纯色底。

## 4. 间距与布局

[H / H03/H06] 采用统一网格，通常以 8vp 为主、4vp 处理细节。同组对齐保持一致。下表是本项目选取的角色，具体场景取值为 [P]：

| 角色 | 紧凑设计值（vp） | 宽松设计值（vp） |
|---|---:|---:|
| 页面左右内边距 | 16 | 24 |
| 卡片内边距 | 16 | 24 |
| 相邻独立区域 | 16 | 24 |
| 卡片内部主要内容组 | 12 | 16 |
| 标签到值/相关元素 | 8 | 8 |
| 紧密的单位与说明 | 4 | 4 |

统一可用尺度：4/8/12/16/24/32vp。不是说 6 或其他值被 SDK 禁止，而是项目默认不让模型随机选值。现有 Skill 的 7/13/34 等散值，建议迁移时逐项替换，不静默改已有产物。

内容高度自然增长；少用固定高度文本框。横排只放短内容，长标题与按钮需要退回纵向。对窄屏、横屏、分屏和大字体做实际验收，不从桌面截图推断。示例 `gap` 按你的锁定有效 Catalog 使用，部分旧 Skill 说明中的白名单并不能替代该基线。

## 5. 圆角与层级

[H / H04] 新版通用圆角的典型档位：4vp 标签、8vp 图片、16vp 内容容器、20vp 按钮/菜单、32vp 弹层。按同层同类保持一致，不能混用旧版圆角表而不注明。

[P] 项目映射：

| 对象 | 设计值（vp） | DSL/宿主边界 |
|---|---:|---|
| 小标签背景 | 4 | 以合法 Text/Row 背景表达，不发明 Badge |
| 图片/缩略图 | 8 | 圆角裁剪需 Image 实测 |
| 普通 Card | 16 | 一层主要外壳 |
| Button | 20 | 不是固定 999；可使用明确的胶囊变体 |
| Modal 外壳 | 32 | 作为宿主主题目标，不给 Modal 虚构专属弹层属性 |

外层 Card 已有背景与圆角，内部 Column 默认不再叠完整阴影壳。项目默认不加阴影：当前 Catalog 的 drop-shadow 格式约束与参考文本存在不一致，未验证前宁用层次、留白和背景区分。

## 6. 对比度与触控

[H / H05] 通用 UX 标准对标题/图标给出大于 3:1、正文大于 4.5:1 的推荐等级要求，不应写成所有元素都只需 3:1。[H / H09] 当前分析器规则对手机等主要交互热区给出 48vp×48vp 推荐、40vp×40vp 最小要求；设计和实际点击区域不是同一件事。

[P] 本项目采用更易执行的门槛：所有承载信息的普通文字目标 >4.5:1，主要控件识别边界/焦点等目标 >3:1；触控目标 48vp×48vp。模板直接输出 `min-height: "48vp"`，实际点击热区仍需端侧量测；样式高度和真实触控区域不自动等同。

本包计算了 14 组**不透明色对**，均超过各自 4.5/3 的目标，详见 `validation/contrast-report.json`。这不是照片背景、半透明叠层、图表、选中态或截图的完整可访问性验收。

## 7. AGenUI 官方 Skill 中吸收与不直接照搬的内容

[A / A01] 吸收：主要层级清楚、内容精炼、CTA 需要真实动作和可见标签；标签与 CTA 不在窄行抢空间；主要外壳不要重复嵌套；保护短词、价格、时间的完整显示。

必须区分的范围：

| 官方文档内容 | 项目处理 |
|---|---|
| 查询摘要卡的高度预算、固定摘要骨架 | 只用于摘要卡，不限制完整交互回复 |
| 不同 Query 不应总套相同布局/配色 | 自由布局；本项目为统一视觉，有意固定语义颜色体系，作为项目偏离记录 |
| 固定 40/36/32/28/24px 字阶 | 保留为官方参考；本项目另采用手机语义字号，以vp直接输出，不能说完全遵循该字阶 |
| 先写结构再写数据、保存文件、完成校验后交付 | 不照搬到在线模式；输入绑定前准备数据，逐区域提交 |
| 原子组件示例中的字段写法 | 与目标有效 Catalog 不一致时，以锁定能力为准，不拼凑版本 |

## 8. 实现层次

1. `visual-tokens.json`：项目设计值，不是可直接提交的 A2UI 消息，也不是 SDK `themeJson` 的正式 Schema。
2. `templates/*.json`：模型可读的组件样式参考，含场景、变体、依赖和可改字段；不是固定业务页。
3. `examples/*.jsonl`：展开后的标准 A2UI v0.9 消息，可作为渲染输入测试。
4. 宿主 Theme：承担原生控件内部字号、选中态、焦点态、深浅色等实际开放的默认样式。

[A / A04] API 存在主题注册及日夜切换，但不能由此推断所有控件内部元素都可逐项改色。硬编码颜色的消息也不因为宿主切换主题就自动改成另一套值。需要宿主 Token 适配，或在发送前按本轮主题展开具体样式。
