# 组件样式模板如何接入现有 agenui-reply

## 1. 不改变你的产品边界

仍然是单轮Query、模型自由组合、在线逐区输出；生成结束后界面内可以继续交互。不增加旧UI多轮修改系统，不将页面固定成火锅/旅行/预算模板。

新增资产承担“同种语义外观一致”，不承担“每个任务都用同一种结构”。组件模板不是可执行任意代码的机制。

## 2. 建议的Skill规则片段

```text
生成A2UI前：
1. 判断普通文本是否已经足够；需要UI时才进入下面步骤。
2. 读取宿主profile、surfaceId和视口；采用已确认的vp单位约定，默认lengthScale=1/fontScale=1。
3. 选择本轮的亮暗主题和密度，按需读取当前要用的组件模板。
4. 按语义角色选Text、Card、Button等变体，而不是每次自行设计样式。
5. 用用户数据或明确标注的假设填写内容，绑定真实路径，调用已启用函数。
6. 尺寸字段保持字符串，默认输出显式vp；无单位尺寸字符串按vp。倍率、百分比和业务数量保持原义。
7. 只输出最终A2UI字段；不输出templateId、token名、注释或未替换占位符。
8. 一批包含完整可用区域及其递归依赖，消息闭合后立即结束该行。
9. 新输入路径在首次绑定前初始化；不得覆盖本轮已显示输入。
10. 后续root保持已显示区域；不为了装饰资源等待整个回复。
11. 不把单位语义已确认或Schema通过等同于视觉、交互或无障碍缩放已通过验收。
```

这是建议加入现有Skill的规则，不是一个替代整个项目的完整SKILL.md。

## 3. 校验程序与Skill分工

| 事项 | Skill | 校验/构建 | 宿主 |
|---|---|---|---|
| 选择适合的UI | 主要负责 | 不替代需求理解 | 提供可用能力 |
| 外观变体 | 按用途选择 | 模板入库校验 | 原生主题实现 |
| NDJSON | 输出正确写法 | 严格解析/完整消息验证 | 缓冲与转发 |
| 数据绑定 | 生成正确关系 | 类型/引用检查 | 写回及依赖更新 |
| 单位 | 按已确认vp约定生成字符串 | 复用项目vp overlay；保留原始vendor | 解释无单位尺寸为vp；验收实际显示与字体缩放 |
| 对比度 | 不随意换色 | 已知不透明色对计算 | 实际合成/状态检查 |
| 动作 | 描述用户可触发动作 | 权限与字段检查 | 点击时求值、执行、反馈 |

## 4. 为什么先入库校验

当前包用指定宿主的 `loadCatalog(profile)` 验证。它包含已有Text样式继承修正、宿主扩展和项目vp单位overlay；原始vendor文件保持不变。因此“通过本项目有效Schema”不等于“上游原始Schema直接支持vp”。每份例子都使用标准 v0.9 外层与完整依赖，catalogId从宿主profile读取。完整文字省略line-clamp，沿用当前宿主契约。

Image/Carousel示例中的`https://example.invalid/...`是不可作为真实图片使用的离线fixture，仅用于验证静态HTTPS字段形态。上线前替换为已核验可访问的无凭据HTTPS直链；校验不会访问图片或验证防盗链。

`visual-tokens.json` 是项目数据。调用 `AGenUI.registerDefaultTheme` 前还需要实际Theme Schema适配；不能把这个文件直接当作API正式参数并宣称可以运行。深浅色切换时，写死的HEX也不会自行转换成暗色，需要真实token映射或本轮输出选色。

## 5. 运行离线检查

使用你的已有Node依赖，Node.js 22+：

```sh
node scripts/validate.mjs --skill /绝对路径/agenui-reply
```

重新生成参考例子（默认1/1直接输出逻辑vp值，无需猜测px换算）：

```sh
python scripts/build_templates.py \
  --skill /绝对路径/agenui-reply \
  --out /输出目录 \
  --length-scale 1 \
  --font-scale 1
```

重新生成不会自动复制说明文档到新目录；本脚本生成模板、示例、Token及基础清单，并在输出目录已有`02_组件模板目录.md`时同步其中的focus JSON片段。`--length-scale`和`--font-scale`是显式项目设计调整，不是单位换算或系统字体缩放；本包标准值固定为1/1。构建后再在目标资料目录运行验证。不得把验证profile中启用Chart等的行为理解成已经为客户端注册实现。

## 6. 当前验证报告

- 25份默认组件例子。
- 29份变体合并检查。
- 2份附加消息示例：联动组合、vp与无单位字符串等价核对。
- 共56项通过指定宿主有效Schema（含项目vp overlay）、引用/初值与结构检查。
- 3项默认profile拦截检查：Chart/Markdown/Lottie未启用时应拒绝，均符合预期。
- 14组不透明颜色对计算，达到各自目标。

没有实际执行任何发送动作。单位语义已由用户确认；未进行HarmonyOS设备视觉、vp与无单位字符串实际显示等价性、系统大字体/无障碍缩放、图片音视频资源访问和端侧表达式重算验证。所有模板的status仍是candidate，不是production-verified。

## 7. 首轮真机验收清单

| 项目 | 操作 | 通过条件 |
|---|---|---|
| 单位 | 使用unit_calibration中16/32/48的vp与无单位字符串配对；对照原生vp参考 | 两种字符串写法在相同环境显示等价；不再猜测2倍系数 |
| 默认/大字体 | 调大系统字体，切窄窗口 | 正文完整，关键内容与操作不遮挡 |
| 浅/深主题 | 同一任务切换 | 对应语义前景背景正常；无白底白字 |
| Text/RichText | 长中文、英文URL、数字单位 | 不挤碎关键信息；富文本不依赖非法字段 |
| Button | 触控、键盘焦点、快速双击 | 热区合格，动作正确且有失败反馈 |
| Slider联动 | 修改每人用量 | 合计正确且不调用模型 |
| ChoicePicker | 单/多选后提交 | 当前string[]正确；不使用旧快照 |
| List | 勾选其中一项 | 不串行、不重置其他条目 |
| Modal | 触发、关闭、返回 | 正确显示并恢复焦点；Text trigger需实测 |
| 追加 | 首批出现后操作，再发送后批 | 用户值保留，结构不整体消失 |
| 图片/媒体 | 资源失败、慢加载 | 有正常布局与宿主错误反馈 |
| Web | 打开现成网页 | 不把内页外观/JS同步当作A2UI保证 |
| 可选扩展 | 未注册/已注册两套环境 | 未注册时明确降级，已注册时逐项验收 |

## 8. 发布方式

维护一个`capabilityVersion + visualVersion + hostUnitProfile`组合。模板变更后用同一组Query做对照测试，分别记录首次语法成功率、样式一致性、首区可用时间和交互正确性。不要以修复后的成功率替代原始生成质量，也不要为追求漂亮而删掉用户需要的交互。
