# v2.3.0 · 模式选择与 DSL 发布验证

本次重构的是给模型读的资料。验收分为两层：模型有没有选择恰当的输出方式；决定使用 UI 后，它输出的消息是否符合既有 v2.1.0 运行契约。后者不能替代前者。

## 资料完整性

模型包从 41 个文件减为 22 个。组件资料由 25 个单页和 1 份索引变为 6 个分册和 1 份索引。组件数量不变：22 种默认，另有须注册并启用的 Chart、Markdown、Lottie。56 个变体名仍映射到 55 段独立模板；Text 的 default 与 body 原本内容相同。18 个函数签名都保留，包含默认关闭的函数。三个独立 NDJSON 和协议页中的最小流均回放通过。

- `npm run check:skill`：由权威源再生成 15 份受管文件，与发布内容逐字节一致。
- `npm run verify:skill`：见 [model-verify.json](model-verify.json)。校验索引锚点、变体初值及节点、启用/禁用扩展、置于真实字段中的函数示例，以及分片输入的完整流。
- `npm test`：104 项通过，无失败。校验内核、有效契约、默认能力、在线门控及 HTTP 运行代码均与上一版本一致。

## 六条请求的首次输出

两组生成会话，各接收三条彼此独立的请求，使用相同的默认能力及分配的 surfaceId；在生成阶段不使用校验器，不读对方的结果，不依据报错重写。本次保留了每条请求的首稿。所有请求、实际模式和文本回复见 [routing-samples.json](routing-samples.json)。无实时桌位和订位能力。

| 请求要点 | 实际表现 |
|---|---|
| 聚餐计划中的 AA 制是什么意思 | 文字解释并举例。|
| 120 元由 4 人平摊 | 直接回答每人 30 元。|
| 带 /agenUI 但明确只要英文译文 | 只输出译文。|
| 仅有店名，要求比较空桌并代订 | 说明查询和代订能力缺失，给出询位话术。|
| 4 人饮料预算，调人均并勾选已买 | [首稿](party-budget.ndjson)：5 条消息、2 个组件批次。滑块的同一数值路径被乘以 4，金额显示保留两位；采购复选框单独初始化，追加时未覆盖预算。|
| 按容量、费用、外饮比较活动室并选择、发送 | [首稿](room-choice.ndjson)：4 条消息、2 个组件批次。第一批可读比较，后一批单选与按钮声明，动作读取点击时所选项。|

两份 UI 原稿均保留最后的 LF，并以未修改的 v2.2 源码包中的 v2.1.0 在线 CLI 原样回放；收到的 9 条消息与原稿逐条 JSON 等价。复核了数据路径、算式、绑定类型及动作声明；未实际发送、预订或在鸿蒙设备上操作。示例是定向抽查，不是目标模型的成功率或端侧效果证明。

从 validator 目录可单独回放：`node scripts/online.mjs --strict-final-newline --surface-id party-budget validation/mode-v2.3/party-budget.ndjson`；第二份文件与 surfaceId 均改为 room-choice 即可。
