## 资料与原协议核对

执行 npm run verify:skill，对实际发布文档提取校验：25种组件、56个变体名（55段独立模板），逐一对比原生成器的初始化数据、组件节点、依赖及顺序，再包装为合法消息通过原单轮门控。选配的 Chart/Markdown/Lottie 分别在启用环境通过、在默认profile拒绝。两页函数表完整覆盖18个函数；4个示例对象放入实际字段/动作位置运行校验。3份完整流及协议页中的两批最小流通过原始字节分片回放。所有资料可从入口沿相对链接到达。详情见发布包内同目录 model-verify.json。

执行 npm run check:skill，从维护源重新生成34份受管文件，与发布目录逐字节一致；执行 npm test，原有104项回归通过。旧发布日志保留为历史资料；本轮测试记录在本目录。

## 两个原始生成样本：无自动修复

重构过程中分别用两个独立生成会话，只读取新版 Skill 资料生成下列任务；没有向生成者提供固定答案，也没有让其使用校验器或重写输出。归档原始输出后，以**未改动的v2.1.0在线CLI**回放，并将接受消息与原始 JSON 逐条比较：

| 请求 | 首次原始输出 | 已核对行为声明 |
|---|---|---|
| 8杯咖啡，每杯用奶可在100–200毫升间调整；勾选豆和冰是否备齐，提交给小艺 | 6条消息 / 3个组件批次，全部通过 | Slider 绑定number；总量读取相同路径按8倍计算；两个独立boolean记录备齐状态；发送动作读取当时的值 |
| 读书会场地：图书馆0元8座不可带饮料，咖啡馆80元12座可带饮料；比较、单选并提交 | 4条消息 / 2个组件批次，全部通过 | 表格保留三项事实；单选初始化为string[]；动作读取场地选择。样本未声明空选时禁止点击，不据此声称它已实现必选拦截 |

原始文件及测试日志仅在双目录源码包的 validator/validation/lean-v2.2/ 中提供，方便复查。两次是覆盖不同生成路径的抽查，没有A/B对照，不是线上首次成功率。未在用户模型、目标HarmonyOS设备或实际发送通道运行。
