# 完整内容、配图与联动

## 把完整回答分配到区域

在内部列出原本会回答的各项信息，按实际任务覆盖结论、对比维度、数字与单位、步骤、条件、例外和已知来源。不必先写完整的 Markdown 或序列化整页。给每项信息安排可从 root 到达的组件，只有数据模型中存在的值还没有展示给用户。

用 Text 承载标题、段落和要点，静态同维度数据可用 Table，链接和短富文本按 RichText 的有效契约处理。首区写核心结论，后续逐区追加清单、证据和细节。长正文可分多个 Text 以保持完整可读；只有信息在别处已完整呈现的非关键摘要才用 `line-clamp: 3`。使用 [Tabs](components/navigation.md#tabs) 分组时，每个选项有可读标题和完整内容，主要结论在首区可见。

## 给适合的对象配图

从用户、宿主或可信来源已提供的素材中挑选能说明对象外观、地点、操作步骤或方案差异的图片。比较多个有图对象时，分别配对应的图；同一对象的多视角可用 Carousel。用 description 或相邻 Text 标明图中对象，必要时写来源和“示意图”。配图随所属区域发送，第一批的文字和操作不依赖图片加载。

用 [Image 或 Carousel](components/media.md)，只用可直连、无鉴权及无已知防盗链限制的 HTTPS 图片地址；Image 设置正宽度。模板地址、网页地址或猜测的图片地址不可用。缺少可靠图源的区域保留完整文字，按已有视觉模板呈现。[图文比较示例](examples/moon-mars.ndjson)展示两组图片、事实和来源。

## 让输入带动结果

为每个控件先列出“用户操作 → 唯一可写数据路径 → 实际消费者”。消费者可以是其他可见组件或需要最新输入的动作；控件本身和仅复述所选值的标签不能代替业务结果。检查两个合法输入，确认所有应变化的结果分别读同一条源路径，初值也能得到正确结果。

| 任务 | 生成做法 |
|---|---|
| 连续数值测算 | 初始化一条 number 路径让 Slider 写入。合计、估价、明细各自在合法动态字段中读取同一路径，用值函数派生。保留 number 中间量，最终用 `formatNumber` 或 `formatCurrency` 展示。后批追加的结果也读该路径，不初始化另一份会失去同步的结果。见[用量测算](examples/portion-planner.ndjson)。 |
| 比较少量预先已知的方案 | 每个 Tabs 标签引用完整方案子树，切换时一并呈现该方案的图片、指标与详细说明。ChoicePicker 的值是 string[]，默认能力无法按该数组动态索引、筛选、取第一项或切换整棵组件树。 |
| 独立记录或提交 | CheckBox 可记录原条目的采购状态。ChoicePicker、TextField 等只用于提交时，给出对应动作及明确标签，并让动作读取点击时的最新值。不得把提交或独立记录描述为实时计算。 |

只用已启用的组件动态字段和[有效函数](functions/builtin.md)。默认 `calculateNumber` 支持加和乘。需要当前契约无法表达的实时计算或条件切换时，使用能完整呈现的静态对比或预计算方案，在组件内说明适用范围。行为以宿主的绑定和重算支持为准。
