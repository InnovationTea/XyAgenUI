# 组件场景选择

本规则用于在生成 A2UI 前判断是否需要 UI，并根据答案的信息结构选择组件。组件名称、字段、枚举和能力只以本 Skill 的 [组件索引](../components/index.md)、[本地 catalog](../vendor/agenui_catalog.json) 和实际宿主 profile 为准。

## 1. 判断是否需要 UI

结合用户问题和准备表达的实际答案，从以下维度判断，不能只按关键词匹配：

- 信息结构：是否存在多个对象、共同维度、数值、时间顺序、层级、选项或用户输入。
- 展示价值：组件化是否能明显降低理解、比较或浏览成本。
- 交互价值：用户是否需要选择、输入、调参、切换视角或继续执行动作。
- 数据完整性：组件所需的文本、分类、数值、初值和真实资源是否具备。

展示模式二选一：

| 模式 | 条件 |
|---|---|
| `NO_UI` | 简单事实、概念解释、普通聊天、翻译、润色、简短代码解释，或组件化没有额外价值 |
| `UI_PRIMARY` | UI 能明显改善理解、比较、浏览或操作效率，并且具备生成真实组件所需的信息 |

用户明确要求 UI 时优先满足，但仍只能使用当前仓库定义且被宿主 profile 启用的组件。

## 2. 组件事实与能力顺序

按以下顺序确定实际组件：

1. 从 `components/index.md` 查找候选组件；索引之外的名称不能出现在 A2UI 输出中。
2. 读取对应组件说明和 schema；字段、枚举和绑定类型以本地 catalog 为准。
3. 检查实际宿主 profile；只有启用的组件才能生成。
4. 默认 profile 未启用的扩展组件，只能在宿主明确注册并启用后使用。
5. 没有合适的已启用组件时，改用普通文本，不得使用组件索引或本地 catalog 中未定义的组件。

当前仓库组件按职责选择：

| 职责 | 实际组件 | 使用边界 |
|---|---|---|
| 文本与指标 | `Text`、`RichText` | 标题、正文、指标、提示和少量行内富文本 |
| 布局与分区 | `Row`、`Column`、`Card`、`Divider` | 横向短信息、纵向区域、语义卡片和必要分隔 |
| 重复与多视角 | `List`、`Tabs`、`Modal` | 重复条目、互斥视角和按需展开的附加信息 |
| 对比与数值展示 | `Table`；profile 启用后可用 `Chart` | 表格用于共同维度；图表仅用于完整且有依据的数值关系 |
| 选择与输入 | `ChoicePicker`、`CheckBox`、`TextField`、`Slider`、`DateTimeInput` | 必须有真实选项、范围、单位、初值或格式要求 |
| 动作 | `Button` | 必须有可见标签和宿主声明的接收方 |
| 媒体 | `Image`、`Video`、`AudioPlayer`、`Carousel` | 图片只用已确认可直连、无防盗链的 HTTPS URL；`Image` 必须设置非零 `styles.width`；轮播只承载图片 URL |
| 辅助与嵌入 | `Icon`、`Web` | 图标不替代文字；Web 仅在任务确需嵌入网页时使用 |
| 可选扩展 | `Markdown`、`Chart`、`Lottie` | 默认关闭，实际 profile 明确启用后才可选择 |

## 3. 信息结构到真实组件

| 信息结构 | 选择条件 | 当前组件组合 |
|---|---|---|
| 同维度比较 | 至少两个对象和两个有意义的共同维度 | `Table`；需要选择时配合 `ChoicePicker`，有接收方时再加 `Button` |
| 分类数值比较 | 每个类别都有可核验数值 | 默认用 `Table` 或 `List`；启用 `Chart` 后可用 `chartType: "bar"` |
| 时间变化 | 有有序时间点和对应数值 | 默认用 `Table` / `List` 并保留趋势结论；启用 `Chart` 后可用 `chartType: "line"` |
| 整体构成 | 各部分属于同一整体且数据完整 | 默认用 `Table` / `List`；启用 `Chart` 后可用 `chartType: "donut"` |
| 顺序、分支或层级 | 有明确步骤、条件分组或父子关系 | 使用 `Column`、`List`、`Card` 组织；互斥视角用 `Tabs`，附加详情用 `Modal` |
| 摘要与关键指标 | 有少量重要结论或数值 | `Card` 内组合 `Text`，少量短指标可用 `Row` |
| 长信息浏览 | 内容可按条目、视角或详情分区 | `List`、`Tabs`、`Modal`，不要做成单个巨大卡片 |
| 代码或配置 | 原格式对理解很重要 | UI 有额外价值且 profile 启用时用 `Markdown`；否则保留普通 Markdown 文本并选择 `NO_UI` |
| 方案选择 | 有真实备选项且用户需要取舍 | `Table` / `Card` 展示差异，`ChoicePicker` 收集选择 |
| 参数测算 | 有范围、单位、初值和受支持计算 | `Slider` / `TextField` / `DateTimeInput` 收集参数，`Text` 展示结果 |
| 偏好收集 | 有单选、多选、布尔项或日期时间 | `ChoicePicker`、`CheckBox`、`DateTimeInput`；需要提交时使用 `Button` |
| 真实媒体浏览 | 已有图片、视频或音频资源且有助任务 | `Image`、`Video`、`AudioPlayer`；多张图片可用 `Carousel` |
| 简单解释 | 普通文本已经清楚 | `NO_UI`，不为了使用组件而卡片化 |

`Chart` 的合法类型由本地 catalog 定义为 `bar`、`line`、`donut`。不得使用组件索引和本地 catalog 中未定义的组件名、字段或图表类型。

## 4. 组合与文字保留

只在每个组件承担不同作用时组合多个 UI：

- 比较与选择：`Table` 或方案 `Card` 展示差异，`ChoicePicker` 承担取舍。
- 结果与说明：`Chart` 或 `Table` 展示数值关系，文字保留结论、单位、数据时间范围和风险。
- 参数与行动：输入组件承载可修改状态，`Text` 展示结果，`Button` 只衔接宿主已声明的动作。
- 浏览与详情：`List` 展示条目，`Tabs` 切换视角，`Modal` 承载非必要的展开内容。

长回答只提取有结构化价值的区域生成 UI，其余内容保留文本。不要用多个组件重复呈现同一份数据。

## 5. 数据与降级约束

1. UI 数据只能来自用户输入、当前对话、可信检索结果或可复核计算。
2. 不补造数值、日期、比例、状态、图片、地点或动作结果。
3. 缺少组件所需数据时，改用文字或通过已启用的输入组件收集。
4. 候选组件未被 profile 启用时，改用表中的其他真实组件。
5. 改用其他组件后若 UI 不再提高理解或操作效率，最终模式改为 `NO_UI`。
6. 不用 `Web` 绕过组件、profile 或能力限制。

## 6. 决策自检

生成前确认：

- 选择依据来自实际答案结构，而非题目关键词。
- 每个组件名称都能在 `components/index.md` 和本地 catalog 中找到。
- 每个输出组件都被当前 profile 启用。
- 字段和枚举来自对应 schema，没有使用本地定义之外的能力假设。
- 每个数值、日期、默认值和媒体资源都有来源。
- 文字与 UI 分工明确，没有重复展示。
