## 五条生成规则

1. **主题背景、半透明卡片、深色墨色。** 根容器使用与内容主题相关的真实背景图；卡片采用半透明浅色底，正文用足够深的黑灰色，强调色从图片与主题中选取。图片不能抢占内容的注意力。
2. **按钮居中、视觉紧凑。** 按钮在所在操作区域水平居中，比常规大按钮小一圈；使用内容宽度和适度内边距，避免默认铺满整行。视觉紧凑仍须保留宿主要求的可点击区域。
3. **标题与多选选项采用 icon/emoji + text。** 图标表达内容含义，后接一个空格与简短文字；不堆叠装饰符号，不用图标代替文字。主标题和分区标题都遵循此格式。
4. **文字精炼。** 结论先行，每个区域表达清楚一个主题；标签短、说明短，删除重复解释，保留数值的单位、条件与必要限定。
5. **展示有层次对比。** 用字号、字重、墨色、底色和留白区分标题、结论、正文与辅助信息；突出主结论与当前操作，不让所有内容同样醒目。

这些是新生成 DSL 的视觉规则；原始样例是协议和交互参考，不能直接沿用其配色与尺度覆盖本规则。用户明确指定其他主题或宿主有视觉限制时按其约束调整，保留可读性和层次。

## 背景与配色

- 需要背景图时主动通过网络搜索与内容主题相关的真实图片，不要求用户先提供图片。选取主体简洁、色调统一、适合作背景的图片，避免文字密集、杂乱或明暗反差过大的画面。只使用确认能被宿主加载的 HTTPS 直接图片地址或已注册资源；禁止 `http://`、搜索结果页和网页地址，不编造链接。确认图片域名允许直接加载且没有防盗链限制，不依赖 Referer、Cookie、登录态或临时授权参数；无法确认时改用纯色背景。记录来源，便于端侧替换或审核。
- 在根组件 `styles` 中设置 `background-image: "url(https://实际图片地址)"`，并设置中性 `background-color` 作为图片加载前或失败时的底色。缺少可用图片、URL 不满足上述要求或宿主禁止外部图片时，使用中性纯色背景，不为凑背景而生成无效 URL。
- 根容器和卡片均设置圆角。根可用 `"border-radius": "20px"`，配合 `"overflow": "hidden"` 裁切背景；具体裁切效果由宿主验收。不要添加 catalog 未定义的 `background-size`、`background-position` 或 `backdrop-filter`。
- 图片上的卡片必须使用半透明浅色底，例如 `"background-color": "#FFFFFFE6"` 或 `"rgba(255,255,255,0.9)"`。图片越复杂，卡片底色越接近不透明；不要用组件整体 `opacity` 制造半透明，这会把文字与控件一起变淡。
- 墨色压深：主文字可用 `#16181D`，正文可用 `#343A40`，辅助文字可用 `#555D66`。颜色写在对应 `Text.styles.color` 上，不假设在根容器设置后所有控件都会继承。根据背景与卡片叠加后的实际效果保证对比，避免浅灰字直接压在图片上。
- 强调内容用与主题、图片色调契合的底色，并搭配能读清的深色文字。优先选择一种强调色及其浅色变体，仅用于结论、关键指标或当前选择；不要把每张卡片涂成不同颜色，也不要只靠颜色区分状态。
- 按钮使用黑底白字或白底黑字，根据所在区域的合成背景选择有明显区别的一组。黑色可用 `#16181D`；浅色按钮落在浅卡片上时，配合深色细边框保留边界。按钮底色设置在 `Button.styles`，字色设置在它引用的 `Text.styles`；不把 `color` 写在 `Button.styles`。

## 图文标签与排版

- 标题可直接使用 `"text": "🥘 火锅采购"`；需要独立图标时，用 `Row` 组合已支持的 `Icon` 与 `Text`，两者通过 ID 引用。只使用 catalog 已定义的图标名。
- 多选项在 `ChoicePicker.options[].label` 中使用 `"🥬 多加蔬菜"` 这样的图文标签；`value` 保持稳定的业务值，不因增加图标而改写数据路径或既有选项值。不要给选项添加未定义的 `icon` 属性。
- 建立清晰的字号层级，例如页面标题 `30px` / `700`、分区标题 `20px` / `600`、正文 `16px` / `400`、辅助说明 `14px` / `400`；关键数值可放大，单位与说明降低层级。字号写在 `Text.styles.font-size`，字重写在 `font-weight`，不要用一套字号贯穿整页。
- **多行文字显式设置不限行数。** `Text` 或 `RichText` 内容预期会换行时，在其 `styles` 中显式设置 `"line-clamp": 0`；本项目 catalog 定义 0 为不限行，可避免省略默认值后端侧出现截断和省略号。不要用正数行数截短内容，也不要设置 `"text-overflow": "ellipsis"`。给文字和父级布局留足高度并使用自然换行；必要时拆成多个语义清楚的段落。多行行高可用 `"line-height": 1.5`。
- **Image 必须有非零宽度。** 每个 `Image` 都要在 `styles.width` 显式设置大于 0 的宽度，例如容器内自适应使用 `"100%"`，定宽缩略图使用合适的 `px` 值；不能依赖 `variant` 推导布局宽度。只使用已确认可直接加载、无防盗链限制的 HTTPS 图片 URL。`Carousel.content` 中的每个图片 URL 和 CSS `background-image` 地址也遵循相同的 HTTPS 与可直接加载要求。

## 间距、圆角与密度

间距从 **2 / 4 / 6 / 7 / 8 / 10 / 12 / 13 / 14 / 16 / 20 / 30** 中选择；圆角从 **34 / 20 / 16 / 14 / 12 / 10 / 999** 中选择，写成带 `px` 的字符串。同一回复固定使用少量尺度，不把所有阶梯都用一遍。

- 根容器默认圆角 `20px`；常规卡片选 `16px` 或 `20px`，内部强调区选 `10px` 或 `12px`，胶囊按钮或标签可用 `999px`。`34px` 留给较大展示卡，不给每一层都叠加大圆角。
- 组内间距小，组间间距大；标题与所属内容靠近，卡片之间留出更明显的空隙。避免重复外壳、多层粗边框与过多分隔线。
- 按钮可从 `"padding": "8px 16px"`、标签 `14px` 起步，按宿主视口调整。使用 `"align-self": "center"`，或放在水平居中的布局容器中；避免 `width: "100%"`、`weight` 或伸展样式把按钮撑满。不要缩小到难以点击。

| 密度 | 适用 | 建议尺度（px） |
|---|---|---|
| 紧凑 | 路线比较、较多条目 | 卡片内边距 12–16，组内间距 6–8，区域间距 12–16 |
| 宽松 | 参数操作、重点指标 | 卡片内边距 20–30，组内间距 10–12，区域间距 20–30 |

表中的区间从上述阶梯选值。同一回复保持一致密度，并根据宿主视口整体调整；协议字号可能经宿主密度换算，不把这些数值直接视为设备上的物理尺寸。长内容纵向展开；横排仅承载能读清的短标签与指标。

## 样式写法

以下是可组合的组件片段，不是完整协议消息。完整组件图还需提供被引用的 `content`，并初始化表单数据；根背景图按上文填入已确认的真实资源。

```json
[
  {
    "id": "summary-card",
    "component": "Card",
    "child": "content",
    "styles": {
      "background-color": "#FFFFFFE6",
      "border-radius": "16px",
      "padding": "16px"
    }
  },
  {
    "id": "summary",
    "component": "Text",
    "text": "🥘 定制火锅采购",
    "styles": {
      "font-size": "20px",
      "font-weight": "600",
      "color": "#16181D",
      "line-height": 1.5
    }
  },
  {
    "id": "submit-label",
    "component": "Text",
    "text": "生成采购清单",
    "styles": { "font-size": "14px", "color": "#FFFFFF" }
  },
  {
    "id": "submit",
    "component": "Button",
    "child": "submit-label",
    "styles": {
      "align-self": "center",
      "background-color": "#16181D",
      "border-radius": "999px",
      "padding": "8px 16px"
    },
    "action": {
      "functionCall": {
        "call": "sendMsgToXiaoyi",
        "args": { "query": "请根据当前偏好${/form/preferences}生成采购清单。" }
      }
    }
  }
]
```

## 按任务组合组件

| 用户任务 | 候选组合 | 交互机会 |
|---|---|---|
| 比较与选择 | 多张方案 Card、同维度 Table、ChoicePicker、Button | 互斥选择绑定 string[]，继续细化读取当前选项 |
| 调参与测算 | Slider / TextField、结果 Text、分区 Card、Button | 参数路径→嵌套值函数→结果；提交当前快照 |
| 收集偏好 | ChoicePicker / CheckBox、DateTimeInput、说明、Button | 每项有初值、限制和单位；宿主保护输入并反馈 |
| 浏览信息 | List / Tabs / 按需 Image、简洁摘要 | 只使用真实媒体资源；无下一步时不硬加按钮 |
| 理解与探索 | 结论 Card、关键指标 Text、分组 List / Tabs、按需 Modal | 将不同视角、解释和细节组织为可切换或展开的内容 |
| 计划与安排 | 阶段 Card / List、DateTimeInput、ChoicePicker、Button | 调整时间与偏好，携带当前状态继续细化计划 |

从实际信息出发组织“结论与概览 → 细节与比较 → 选择或调整 → 后续行动”，根据任务组合适用区域。已知多个方案时主动提供便于比较的结构；有可调参数且宿主支持计算时主动提供输入与联动结果；有真实媒体且有助理解时使用对应媒体组件。能力不足时保留受支持的表达方式，不生成无效控件。

按任务选取上述组合，不设组件数量或种类配额。表格用于同维度对照，单选用于决定，二者可以组合；展示结论的同时，可以提供相关探索和后续操作。静态内容写入组件，用户能改的参数进入数据模型。

## 视觉自检

交付前检查：每个预期多行显示的 `Text` / `RichText` 都显式设置 `styles.line-clamp: 0`，文字无省略或裁切；每个 `Image` 都在 `styles.width` 设置大于 0 的宽度；所有图片（包括 Carousel 和背景图）都使用 HTTPS 直接地址，并确认域名允许无防盗链直接加载；缺少合格图片时有可读的纯色回退。另检查半透明卡片上的文字足够深、强调底色呼应主题、按钮居中紧凑且容易点击、标题与多选标签带有语义图标、文案精炼、字号墨色间距和圆角形成一致层次。窄屏下标签、单位和操作仍须清晰可见。

DSL 校验只检查字段、类型和结构，不能证明图片可达、颜色对比、控件触达或真实视觉效果。样式不能突破组件 schema：不为 Slider 虚构轨道/圆点颜色属性，不为 ChoicePicker 的每个选项添加不存在的样式字段；实际显示按已有宿主验收。
